# Todo Notes

Адаптивное SPA приложение для заметок со списками задач. Проект выполнен на Nuxt 4, Vue 3 и TypeScript в строгом режиме без UI-библиотек.

## Возможности

- создание, редактирование и удаление заметок;
- добавление, изменение, удаление и отметка задач;
- краткий просмотр задач на главной странице;
- подтверждение опасных действий через собственные модальные окна;
- отмена и повтор изменений кнопками и горячими клавишами;
- история до 50 операций без хранения полных копий заметки;
- сохранение заметок в версионированном `localStorage`;
- отложенное сохранение незавершённого черновика;
- предложение восстановить черновик после перезагрузки;
- синхронизация заметок между вкладками;
- обработка прямого перехода к несуществующей заметке;
- адаптивный интерфейс и полная клавиатурная навигация

## Технологии

- Nuxt 4;
- Vue 3, Composition API;
- TypeScript с `strict: true`;
- Pinia;
- SCSS;
- Vitest;
- Docker и Docker Compose.

## Требования

- Node.js 24.15 или новее;
- npm 11 или новее;
- современный браузер;
- Docker Desktop или Docker Engine с Compose для запуска в контейнере.

## Локальный запуск

Установите зависимости:

```bash
npm ci
```

Запустите сервер разработки:

```bash
npm run dev
```

Приложение будет доступно по адресу [http://localhost:3000](http://localhost:3000).

## Проверки

Запуск unit-тестов:

```bash
npm test
```

Проверка TypeScript:

```bash
npx nuxt typecheck
```

Production-сборка:

```bash
npm run build
```

Локальный просмотр production-сборки:

```bash
npm run preview
```

## Запуск через Docker

Соберите и запустите приложение:

```bash
docker-compose up --build
```

Для Docker Compose v2 также доступна команда:

```bash
docker compose up --build
```

После запуска приложение будет доступно по адресу [http://localhost:3000](http://localhost:3000).

Чтобы использовать другой внешний порт, задайте переменную `APP_PORT`. Пример для PowerShell:

```powershell
$env:APP_PORT=8080
docker compose up --build
```

Остановка контейнера:

```bash
docker compose down
```

Docker образ собирается в несколько этапов. В итоговый образ попадает только production сборка Nuxt, а приложение запускается от непривилегированного пользователя. Для контейнера настроена проверка состояния.

## Горячие клавиши

| Действие | Windows/Linux | macOS |
| Отменить изменение | `Ctrl+Z` | `Cmd+Z` |
| Повторить изменение | `Ctrl+Shift+Z` | `Cmd+Shift+Z` |

В текстовых полях эти сочетания сохраняют нативное поведение браузера. Глобальная история применяется, когда фокус находится вне текстового поля.

## История изменений

История реализована вручную в `app/utils/noteHistory.ts`.

- Каждая операция содержит только изменённые данные, а не полную копию заметки.
- Добавление, удаление и отметка задачи записываются как отдельные операции.
- Непрерывный ввод текста фиксируется одной операцией после потери фокуса.
- Новое действие после `undo` очищает ветку `redo`.
- Максимальный размер истории 50 операций.
- Сохранение и отмена редактирования очищают историю.

## Хранение данных и черновиков

Синхронизация Pinia с `localStorage` реализована вручную.

- Сохранённые заметки находятся по ключу `todo-notes:data`.
- Черновики используют ключи с префиксом `todo-notes:draft:`.
- Сохраняемые структуры содержат версию схемы и проходят проверку при загрузке.
- Черновик записывается после паузы в 700 мс, а также перед закрытием или перезагрузкой страницы.
- После сохранения, удаления или подтверждённой отмены черновик очищается.
- Событие `storage` обновляет данные в других открытых вкладках.

Данные хранятся в браузере, поэтому перезапуск Docker-контейнера их не удаляет.

## Доступность

- модальные окна реализованы на нативном элементе `dialog`;
- фокус удерживается внутри открытого окна;
- `Escape` закрывает модальное окно;
- все действия доступны с клавиатуры;
- интерактивные элементы имеют заметное состояние фокуса;
- учитывается системная настройка `prefers-reduced-motion`.

## Структура проекта

```text
app/
├── assets/scss/       глобальные стили
├── components/        переиспользуемые компоненты
├── pages/             главная страница и редактор заметки
├── plugins/           загрузка и синхронизация данных
├── stores/            Pinia-стор и его тесты
├── types/             модели данных
└── utils/             хранилище, черновики и история изменений
```

Unit-тестами покрыты логика истории, хранилище черновиков и Pinia стор. Компонентные тесты не используются согласно требованиям задания.
